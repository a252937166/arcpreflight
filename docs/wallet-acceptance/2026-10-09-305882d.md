## Remaining presentation findings (not fixed in this session)

1. **Transient false review-required result after buying a report.** The page briefly displayed preflight review required / nothing executed / export active, then corrected to no policy violation / execute active after the baseline loaded. `apps/web/src/pages/Developer.tsx:248` clears the baseline when `delivered` changes; decision calculation at lines 118–120 can interpret the loading interval as a missing approved baseline. Keep an explicit loading state and defer the decision/lifecycle stop until the baseline read finishes. The transient was observed in browser tool output; its exact reason payload was not captured, so the source path is the likely explanation rather than a separately reproduced fault-injection result.
2. **Header balance stays stale after payment.** The header retained 0.18 USDC while the Developer wallet balance had become 0.1170 USDC, and later required reload to show 0.06. Evidence: `09-s12-creation-start.txt` and earlier snapshots. `WalletChip.tsx:44–46` and `Developer.tsx:96–98` instantiate separate balance hooks; only the Developer instance refreshes on workflow changes. Share balance state or invalidate all views on fee/payment completion and cross-tab changes.

The missing-MetaMask blocker was resolved by the user's Chrome extension site-access change. Before it, Chrome listed MetaMask under “Access requested,” and provider announcements contained only OKX/Phantom. Afterwards, announcements included `MetaMask / io.metamask`; both fresh and duplicated tabs connected correctly. Do not attribute the permission change to an application-code fix alone.

These results close the two outstanding real-extension testnet scenarios from the earlier session and the creation-state re-check. They do not rerun every scenario on this release or constitute mainnet acceptance. Mainnet remains NOT_RUN. No source code was changed, no commit or push was made, and no mainnet transaction was signed in this session.
