   although a PLANNED identity was persisted. Order `0x1442b29215cdb81644f195aac63d19e9629c94237d890952e0f5020ca8f94c94`
   had no recorded hash and did not exist on chain; after the reconciliation window it became UNKNOWN_CREATION.
   The creation path does not use the identical-byte retry added for runner business payment. Its broadcast identity and
   recovery/error behavior need review; do not blindly replace or rebroadcast an uncertain creation.
2. Selecting that PLANNED row through `use` marked Create order done and payment unpaid, and allowed approval/quote flow.
   The detail card simultaneously said planned / not recorded yet / not read yet. Gate progression on confirmed creation
   and preserve unknown payment state in all summaries.
3. MetaMask discovery on new tabs failed in this multi-wallet browser. The exact extension cause is not established.
   Discovery requests provider announcements only once; the remembered-name legacy fallback also risks mislabelling OKX
   as MetaMask. Fix/reproduce provider selection, then rerun S10 with two real MetaMask tabs.
4. Complete actual chain-RPC delay coverage for S12. Keep this distinct from browser/API throttling.
5. MetaMask displayed the transaction amount as `0.001 SepoliaETH` while the request network and gas unit were Arc Testnet / USDC
   after network switching. Chain evidence confirms the transaction was on 5042002. Track this as an extension/display observation,
   not as a wrong-chain transaction or a proven application root cause.
