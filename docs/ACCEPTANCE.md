**Status values**

| Value | Rule used in this record |
|---|---|
| PASS | Every sub-case that applies to the enabled release has a concrete reference. |
| PARTIAL | Some sub-cases are referenced; the missing ones are named in the note. |
| FAIL | Executed and failed. None recorded. |
| NOT_RUN | No reference. Where the feature is not implemented, the note says so. |
| NOT_APPLICABLE | Feature closed or absent, and copy narrowed accordingly (§12.1). |

Code or a UI control is never taken as PASS. Multi-sub-case scenarios are PARTIAL until every applicable sub-case has a reference.

**Requirement classes** (§12.1): REQUIRED_ENABLED, REQUIRED_REJECTION, DEFERRED_FEATURE, DEFERRED_DEPTH. "A + B" means both parts apply. For a closed capability the rejection is the required part, so the status shown is that of the rejection check; the positive-path tests are DEFERRED_FEATURE and are named in the note.
